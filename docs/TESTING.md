# Проверки LANPrint 0.1.0

## Выполнено в Linux Docker

Основная сборка запускает 12 функциональных/unit-тестов core с race detector и два seed-case fuzz-цели `FuzzDecodeIPP`. Проверяются:

- валидация конфигурации, разрешённых CIDR, конкретного IPv4 и round-trip сохранения;
- Static IP, маска, адрес сети/broadcast, шлюз, DNS;
- MIME/UTF-8, корректный PNG и отклонение неверного MIME/PDF;
- последовательная очередь, её переполнение и отмена pending/spooled;
- ограничение размера, запрещённый RAW и ошибка отключённого принтера с fake backend;
- отмена активного fake backend при остановке;
- IPP Print-Job, Get-Printer-Attributes, ошибка формата, авторизация отмены;
- обрезанные/повреждённые IPP-пакеты;
- DNS-SD records и циклический DNS compression pointer;
- **реальные TCP listeners**: RAW документ доставлен fake backend, HTTP auth/status, IPP attributes, освобождение портов при остановке;
- шесть одновременно подключающихся RAW клиентов, последовательно доставленных backend;
- отклонение IPP клиента вне ACL и слишком большого HTTP body.

Windows EXE кросс-компилируется исключительно в Docker, экспортируется в корень и проверяется SHA-256. Это не проверка запуска Windows, GDI или физического принтера. Полный `go test -race ./...` также выполняется в Docker; GUI/platform пакеты не имеют исполняемых Linux-тестов.

Дополнительно выполнены в Docker: Windows-target `go vet ./...` (без замечаний), 10 секунд IPP fuzz-теста / 146 464 executions (PASS), независимая сборка `--no-cache` с совпадением SHA-256. Контрольная сумма EXE: `a008f378155388cbbc4f9e17acbb53b327a4e04a590a705a7bfc42c4b1871f01`. Эти проверки не заменяют следующую матрицу приёмки.

## Аппаратная/внешняя приёмка — пока не выполнена

| № из ТЗ | Сценарий | Статус / способ проверки |
|---|---|---|
| 1 | Docker → корневой LANPrint.exe | Выполнено в текущей Linux-среде; отдельно повторить на выбранном VPS |
| 2 | Запуск Windows 10 x64 | Не выполнено; открыть GUI и проверить завершение/трей |
| 3 | USB-принтер | Не выполнено; Get-Printer, выбор в GUI, физический лист |
| 4 | Выбор NIC | Linux bind/ACL проверены; Windows/другой LAN хост не проверены |
| 5 | DHCP | Не выполнено; изменение lease, новый bind и Firewall, доступ с LAN клиента |
| 6 | Static | Валидация проверена; применение Windows/UAC/DAD не проверено |
| 7 | Отдельный Bridge IP | Не выполнено; Hyper-V External Switch, два MAC/IP, клиент в LAN |
| 8 | Обнаружение LAN | DNS-пакеты проверены; mDNS реальными клиентами не проверен |
| 9 | Физическая печать | Fake backend проверен; реальная GDI/RAW/Spooler печать не проверена |
| 10 | Потеря сети/принтера | Ошибка fake backend проверена; Windows recovery и hardware disconnect не проверены |
| 11 | Перезагрузка/автозапуск | Не выполнено; reboot → вход пользователя → восстановление служб |
| 12 | Actions/Release | Workflow подготовлен; результат проверяется по фактическому GitHub run/asset |

Для физической приёмки подготовьте UTF-8 текст на несколько страниц, PNG с прозрачностью, JPEG, совместимый PCL/PostScript документ (если RAW включён). Проверьте бумажный результат, последовательность нескольких клиентов, отключение USB во время работы, повторный запуск и отмену. Не отправляйте PDF/Office в RAW без гарантии native поддержки принтера. Сравните SHA-256 опубликованного EXE с собранным из того же тега.

`scripts/check-windows.ps1` проверяет только текущие принтер/NIC/IP/порты и authenticated HTTP status. Настоящую печать выполняйте кнопкой GUI или `scripts/ipp-print.py` и проверьте отпечаток. Bridge обязательно проверяйте со второго физического устройства.
