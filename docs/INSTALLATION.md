# LANPrint 0.2.0 — установка на Windows 10 x64

## Требования

Windows 10 Pro/Enterprise/Education x64 с аппаратной виртуализацией и Hyper-V, физический Ethernet и LAN с DHCP (либо свободный статический адрес). Windows Home не поддерживает Hyper-V: программа сообщает об ограничении и не использует IP физического адаптера. Wi-Fi bridge в этой реализации не поддерживается. Если BIOS/UEFI отключает виртуализацию, включите её перед настройкой.

Установите локальный USB/иной принтер с драйвером Windows и проверьте тестовую страницу средствами Windows. Служба Print Spooler должна работать.

## Создание виртуального сетевого устройства из EXE

1. Соберите EXE в Docker на своём VPS (`bash build.sh`) или скачайте его и SHA-256 из Releases одной версии. Сравните контрольную сумму. Сохраните EXE по постоянному пути, например `C:\LANPrint\LANPrint.exe`.
2. Запустите EXE обычным пользователем. Настройки и случайный токен создаются в `%LOCALAPPDATA%\LANPrint\config.json`.
3. Нажмите «Обновить». В «Подключение к LAN» выберите физический Ethernet. Этот список выбирает **uplink**, а не адрес службы принтера.
4. Укажите VLAN ID: 0 — нетегированная LAN, 1–4094 — tagged VLAN. Нажмите **«Создать / VLAN…»**, прочитайте описание изменений и подтвердите UAC. Выполняйте это с локальной консоли: создание External Switch может временно прервать Ethernet/RDP. Запишите исходные IP/DNS/шлюз основной сети.
5. Приложение проверит редакцию Windows, физический адаптер и поддержку Hyper-V. Если Hyper-V не включён, включит компонент без автоматического reboot, покажет сообщение о необходимой перезагрузке. После reboot снова нажмите «Создать / VLAN…».
6. На выбранном Ethernet создаётся внешний Hyper-V switch `LANPrint`, либо используется уже существующий External Switch этого uplink. Затем добавляется отдельный ManagementOS адаптер **`LANPrint-Printer`**, в Windows — **`vEthernet (LANPrint-Printer)`**, с собственной MAC. Основное ManagementOS подключение Windows сохраняется. Если существующий LANPrint адаптер относится к другому switch/uplink, программа остановится с ошибкой и не переподключит его.
7. Новый виртуальный адаптер включает DHCP и ожидает пригодного IPv4 до 45 секунд. Он должен получить **отдельную аренду DHCP из вашей LAN**. Если адрес не пришёл, адаптер всё равно остаётся доступным для настройки Static IP. Адрес `169.254.*`, Duplicate/Tentative и отсутствие IPv4 не используются для служб.
8. В «Адаптер принтера» показывается только выделенный виртуальный интерфейс и его адрес. Основной IP Windows нельзя выбрать как endpoint принтера. Повторное создание использует существующий корректный adapter/switch и не сбрасывает настроенный Static IP.
9. Выберите локальный принтер и имя в LAN. При «Запустить» без виртуального адаптера приложение также предложит создание. При наличии адаптера без адреса перейдёт в ожидание DHCP и запустит службы, когда IPv4 появится.
10. Сохраните настройки. При переносе с 0.1.x прежний Shared IP не используется; принтер/токен сохраняются в памяти, endpoint переводится на выделенный виртуальный адаптер. Миграция сама по себе не изменяет сетевую конфигурацию Windows.

PowerShell помощник создания встроен в EXE. Для обычного пользователя отдельные скрипты/исходники не нужны. Приложение ждёт завершения elevated помощника и читает его результат; при отмене UAC или ошибке не объявляет настройку успешной. После частичной ошибки изучите `Get-VMSwitch`, `Get-VMNetworkAdapter -ManagementOS` и `Get-NetAdapter`, прежде чем повторять действие.

## VLAN на uplink и мост к виртуальному интерфейсу

Для tagged сети схема такова: Ethernet uplink получает 802.1Q VLAN N → внешний Hyper-V switch выделяет VLAN N на порту LANPrint → отдельная виртуальная NIC → DHCP этой VLAN → службы на её IPv4. Windows Hyper-V выполняет VLAN tagging/filtering на switch port, а не создаёт Linux-подобный `Ethernet.N` подинтерфейс. Создание VLAN объектов драйвером физической NIC зависит от модели/драйвера и здесь не используется. Сам Windows виртуальный адаптер получает кадры после снятия тега.

- VLAN 0: `Set-VMNetworkAdapterVlan ... -Untagged` на выделенной NIC; это значение GUI для untagged, а не priority-tagged VLAN 0.
- VLAN N (1–4094): `Set-VMNetworkAdapterVlan -ManagementOS -VMNetworkAdapterName LANPrint-Printer -Access -VlanId N`.
- Разрешите VLAN N как tagged на физическом switch port; сохраните требуемую native/untagged VLAN для основного подключения Windows. Программа не конфигурирует физический сетевой коммутатор/роутер.
- DHCP должен присутствовать в выбранной VLAN (либо через настроенный DHCP relay), шлюз/Static subnet также должны относиться к ней. После смены VLAN DHCP виртуальной NIC выполняет release/renew; прежний адрес native VLAN не должен использоваться.
- Для смены VLAN остановите службы, измените поле и нажмите «Создать / VLAN…». Указание нового ID само по себе не меняет сеть. При существующей Static конфигурации IP не удаляется автоматически: настройте адрес/шлюз новой VLAN явно.
- Проверьте применённый VLAN elevated командой `Get-VMNetworkAdapterVlan -ManagementOS -VMNetworkAdapterName LANPrint-Printer`, DHCP leases на роутере и печать с другого ПК в VLAN N.

Это выделенная Access VLAN, а не trunk со множеством тегов внутри Windows NIC. Hardware VLAN filtering в драйвере физической карты не должен отбрасывать VLAN N до Hyper-V; при ограничениях драйвера/port security потребуется настройка сети администратором. Фактическая tagged/DHCP/Bridge проверка на Windows пока не выполнена.

## DHCP / Static только на виртуальном адаптере

1. Остановите службы (включая ожидание адреса).
2. В «Адаптер принтера» выбран `vEthernet (LANPrint-Printer)`.
3. DHCP: «Применить DHCP…», подтверждение/UAC; настройки этой виртуальной карты переходят на DHCP. Затем «Обновить».
4. Static: задайте IPv4, непрерывную маску /1–/30, шлюз из той же подсети и необязательные DNS IPv4 через запятую. Проверьте отсутствие адреса в DHCP pool/IPAM роутера. «Применить Static…», подтверждение/UAC; после завершения PowerShell окна — «Обновить».
5. Сохраните и запустите службы. Изменения относятся только к выделенной виртуальной карте; DHCP/Static физического uplink из GUI не настраиваются.

Программа не доказывает отсутствие конфликта по отсутствию ping-ответа. Windows DAD может сообщить Duplicate после назначения. Сетевые изменения не транзакционные; при ошибке восстановите параметры выделенной карты вручную. Высокая interface metric нового виртуального адаптера уменьшает влияние его gateway на основной маршрут хоста.

## Firewall и первый тест

Службы: TCP 9100 (RAW), TCP 8631 (IPP), TCP 8765 (управление), UDP 5353 (mDNS). Разрешайте их только в доверенной LAN на виртуальном интерфейсе. Для скрипта Firewall скачайте каталог `scripts` из репозитория той же версии:

```powershell
cd C:\LANPrint
.\scripts\firewall.ps1 -Address 192.168.1.55 -InterfaceAlias 'vEthernet (LANPrint-Printer)'
```

Команда требует elevated PowerShell и подтверждения; подставьте фактический адрес виртуальной карты. Правила для Private профиля и LocalSubnet. При DHCP смене IP обновите адрес-специфичное правило; приложение самостоятельно Firewall не меняет. Удобна DHCP reservation для MAC виртуальной карты.

Нажмите «Запустить» и «Тестовая печать». Проверьте очередь Spooler и реальный лист. HTTP интерфейс открывается кнопкой управления; вводите токен из GUI, не передавайте его в URL и не публикуйте сервис в Интернет.

## Проверка отдельного устройства из LAN

```powershell
Get-NetAdapter -Name 'vEthernet (LANPrint*)' | Format-Table Name,MacAddress,Status
Get-NetIPAddress -InterfaceAlias 'vEthernet (LANPrint-Printer)' -AddressFamily IPv4
Get-VMNetworkAdapter -ManagementOS -Name LANPrint-Printer | Format-List Name,MacAddress,SwitchName
```

Проверьте на роутере две отдельные MAC/IP записи: Windows host и LANPrint. **Со второго физического компьютера в той же LAN** проверьте IPP attributes и реальную печать на адрес LANPrint. Проверка только с самого хоста не подтверждает L2 bridge. Сеть/коммутатор/port security должны разрешать несколько MAC за Ethernet портом.

Экспериментальная аппаратная проверка Hyper-V, DHCP и физической печати здесь не выполнена. При несовместимости программа сообщает об ошибке; прямого fallback на физический интерфейс нет.

## Клиентская печать

IPP URI: `ipp://VIRTUAL_IP:8631/ipp/print`. Поддерживаются UTF-8 `text/plain`, PNG и JPEG; PDF/PWG/URF/Office, полный IPP Everywhere, AirPrint/Mopria не реализованы. Пример без сторонних Python библиотек:

```bash
python3 scripts/ipp-print.py --host 192.168.1.55 --file sample.txt --format text/plain
```

CUPS ipptool может проверить attributes: `ipptool -tv ipp://192.168.1.55:8631/ipp/print get-printer-attributes.test`.

Для обычной печати из Windows приложений через TCP 9100 нужен драйвер клиента, выдающий поддерживаемый физическим принтером PDL (например PCL/PostScript). Включите RAW passthrough в LANPrint, добавьте на клиенте Standard TCP/IP Port с **виртуальным IP**, RAW/9100, отключённым SNMP status, установите совместимый драйвер и проверьте физический результат. Host-based/GDI-only принтеры могут не поддерживать такой passthrough; для них передавайте поддерживаемые IPP документы с рендерингом на сервере. По умолчанию 9100 принимает UTF-8 текст до закрытия соединения, не произвольный PDF/Office.

## Автозапуск и остановка

При остановленных службах включите «Запуск при входе в Windows» и сохраните. HKCU Run запускает EXE с `--autostart`; после входа пользователя приложение ожидает сохранённый виртуальный интерфейс/IP и восстанавливает listeners. При автозапуске сеть без подтверждения не создаётся/не меняется. Это пользовательский процесс, не системная служба до входа.

Крестик скрывает окно в трей. «Выход» останавливает службы и завершает EXE. Виртуальная карта и switch сохраняются в Windows после выхода/перезагрузки; приложение не удаляет их автоматически. Очередь LANPrint в памяти не переживает restart; переданные Spooler задания остаются у Windows.

Удаление виртуального адаптера и switch выполняйте вручную с локальной консоли после проверки их зависимостей. Не удаляйте общий External Switch, если его используют другие VM/сервисы; восстановите основное подключение хоста при удалении созданного switch.
