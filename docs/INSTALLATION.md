# Windows 10 x64: установка и запуск

## Первый запуск

1. Установите драйвер физического USB/локального принтера и распечатайте тестовую страницу средствами Windows. Служба Print Spooler должна работать.
2. Соберите EXE на Linux VPS по `BUILD.md` либо скачайте релиз той же версии. Проверьте SHA-256. Храните EXE в постоянной папке, например `C:\LANPrint`, вместе с `scripts` и `docs` из той же версии репозитория.
3. Запустите `LANPrint.exe` обычным пользователем. Программа создаст конфигурацию и случайный 256-битный токен в `%LOCALAPPDATA%\LANPrint\config.json`.
4. Нажмите «Обновить», выберите интерфейс/его IPv4, физический принтер и имя сетевого принтера. В режиме общего IP флажок Bridge выключен.
5. По умолчанию используются TCP 9100, IPP/HTTP 8631, HTTP управления 8765, UDP mDNS 5353. IPP URI: `ipp://IP:8631/ipp/print`. Все TCP listeners привязаны только к конкретному выбранному IPv4.
6. Нажмите «Сохранить». Дополнительные лимиты, CIDR ACL и порты редактируются в конфигурации при остановленном приложении. После изменения конфигурации перезапустите EXE.
7. Если ваша LAN не входит в `10/8`, `172.16/12`, `192.168/16`, добавьте её CIDR в `allowed_cidrs`. Не используйте `0.0.0.0/0` без необходимости.
8. Разрешите доступ в Windows Firewall (PowerShell от администратора, подставьте фактический IP и alias):

```powershell
cd C:\LANPrint
.\scripts\firewall.ps1 -Address 192.168.1.50 -InterfaceAlias Ethernet
```

Правила предназначены для профиля Private и LocalSubnet. Проверьте сетевой профиль через `Get-NetConnectionProfile`. Менять Public на Private следует только для доверенной LAN. При изменении DHCP IP повторно примените правило с новым адресом; приложение не изменяет Firewall самостоятельно. Для постоянной доступности удобна DHCP-резервация на роутере.

9. Нажмите «Запустить», затем «Тестовая печать». Убедитесь в появлении задания в очереди Windows и фактическом выходе листа.
10. HTTP управление открывается кнопкой. Введите токен из GUI; он не передаётся в URL и не хранится браузером. Не открывайте этот HTTP сервис в Интернет.

## DHCP и Static

DHCP/Static применяются **к выбранному Windows-адаптеру**, а не к контейнеру. В Shared режиме изменение физических сетевых параметров меняет сеть самого ПК. Bridge использует отдельный выделенный виртуальный адаптер.

1. Остановите службы.
2. Выберите нужный адаптер. Для Bridge выбирайте только `vEthernet (LANPrint-Printer)`.
3. DHCP: нажмите «Применить DHCP…», подтвердите изменение и UAC. Настройки DNS возвращаются к DHCP.
4. Static: заполните IPv4, непрерывную маску /1–/30, шлюз этой подсети и необязательные DNS IPv4 через запятую. Нажмите «Применить Static…», подтвердите изменение и UAC. **Проверьте отсутствие адреса в DHCP-пуле/таблице DHCP/IPAM роутера**; отсутствие ping-ответа не доказывает свободный IP. Windows DAD также может обнаружить дубликат после назначения.
5. Дождитесь завершения отдельного PowerShell окна, нажмите «Обновить», выберите новый адрес и сохраните настройки. При DHCP выдача адреса может занять время; `169.254.*` означает отсутствие DHCP.

Изменение сети может прервать RDP. Выполняйте его с локальной консоли и запишите исходные параметры. PowerShell окно показывает ошибки; отмена UAC не меняет сеть. Изменения не транзакционные: при ошибке проверьте состояние и восстановите исходные параметры. Выбор адаптера и запуск служб сами по себе сеть не изменяют.

## Отдельный IP — Hyper-V Bridge

Требуется Windows 10 Pro/Enterprise/Education x64, Hyper-V, аппаратная виртуализация и Ethernet, допускающий несколько MAC. На Windows Home используйте явно обозначенный Shared режим. Wi-Fi/корпоративный port security могут не допускать нужную L2 схему.

Схема: физический Ethernet → внешний Hyper-V коммутатор → обычный ManagementOS адаптер Windows **и дополнительный ManagementOS адаптер LANPrint-Printer с собственной MAC/IPv4**. EXE работает на хосте и слушает только адрес второго адаптера. Это не Docker NAT/port publishing. Изоляция здесь означает отдельный endpoint; виртуальный адаптер остаётся частью сетевого стека Windows.

1. С локальной консоли включите Hyper-V и перезагрузитесь, если он ещё не включён:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All -All
```

2. Запишите IP/DNS/шлюз исходного Ethernet. Проверьте отсутствие чужих Hyper-V switch на этом адаптере.
3. В PowerShell администратора из папки проекта выполните:

```powershell
.\scripts\bridge.ps1 -AdapterName Ethernet
```

Скрипт требует подтверждения. Создание внешнего switch кратковременно прерывает сеть; основной адрес хоста может перейти на `vEthernet (LANPrint)`. Повторный запуск не перезаписывает существующий switch. Скрипт создаёт `vEthernet (LANPrint-Printer)` и включает DHCP. Если операция завершилась частично, сначала изучите `Get-VMSwitch` и `Get-VMNetworkAdapter -ManagementOS`, не запускайте её вслепую.

4. Выберите `vEthernet (LANPrint-Printer)` в GUI, включите Bridge. Настройте DHCP/Static только на нём. Проверьте отдельную MAC и IPv4:

```powershell
Get-NetAdapter -Name 'vEthernet (LANPrint*)' | Format-Table Name,MacAddress,Status
Get-NetIPAddress -InterfaceAlias 'vEthernet (LANPrint-Printer)' -AddressFamily IPv4
Get-NetIPAddress -InterfaceAlias 'vEthernet (LANPrint)' -AddressFamily IPv4
```

5. Добавьте Firewall правила на выделенный alias/IP и запустите службы.
6. **С другого ПК в той же LAN** проверьте доступ к отдельному IP, IPP attributes и реальную печать. В таблице DHCP/ARP роутера должны быть два разных MAC/IP. Проверка только с самого хоста не подтверждает L2 bridge.

Эта схема требует экспериментальной проверки на вашем оборудовании; в Linux CI она не проверяется. При несовместимости используйте Shared режим и отметьте Bridge как непрошедший приёмку. Удаление switch и восстановление основной сети выполняются вручную с локальной консоли после остановки LANPrint. Не удаляйте другие коммутаторы/адаптеры.

## Клиентская печать

Для IPP клиент должен отправлять один из объявленных MIME: UTF-8 текст, JPEG или PNG. Полный IPP Everywhere, PWG Raster, PDF, AirPrint/Mopria не реализованы. На Linux/macOS при установленном CUPS можно отправить поддерживаемый документ напрямую:

```bash
ipptool -tv ipp://192.168.1.50:8631/ipp/print get-printer-attributes.test
```

Для печати текста используйте `scripts/ipp-print.py` (Python 3, без сторонних библиотек):

```bash
python3 scripts/ipp-print.py --host 192.168.1.50 --file sample.txt --format text/plain
```

TCP 9100 по умолчанию также принимает UTF-8 текст до закрытия соединения клиентом. Для стандартной печати из приложений Windows:

1. Убедитесь, что физический принтер поддерживает PDL, выдаваемый клиентским драйвером (например PCL6/PostScript). Host-based принтеры часто не подходят.
2. В LANPrint включите **RAW passthrough** и подтвердите предупреждение.
3. На клиенте: «Принтеры и сканеры» → «Добавить» → «Необходимый принтер отсутствует» → «Добавить по TCP/IP».
4. Адрес — выбранный IP LANPrint. Настройте Standard TCP/IP Port, RAW, порт 9100. Отключите SNMP status для этого порта: SNMP не реализован.
5. Установите совместимый драйвер физического принтера, распечатайте тестовую страницу и документ. Неподдерживаемый PDL может вызвать мусорную печать; тестируйте осторожно.

## Автозапуск и трей

Включите «Запуск при входе в Windows» и нажмите «Сохранить». Запись HKCU Run запускает этот EXE с `--autostart`. Службы восстановятся с сохранёнными настройками после входа этого пользователя, при появлении нужного адаптера. Это не служба до входа в систему. Сохраняйте EXE по постоянному пути. Для отключения снимите флажок и сохраните.

Крестик прячет окно в трей; щелчок по значку возвращает его. «Выход» останавливает службы и завершает процесс. Изменения выбираемого принтера/имени/режима применяются при повторном запуске служб. Незавершённая очередь LANPrint не переживает остановку/перезапуск; уже переданные Spooler задания остаются у Windows.
