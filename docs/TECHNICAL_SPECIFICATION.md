# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Разработка приложения LANPrint — эмулятор сетевого принтера для Windows 10

**Версия ТЗ:** 1.0\
**Название проекта:** LANPrint\
**Целевая операционная система:** Windows 10 x64\
**Формат приложения:** EXE\
**Система сборки:** Docker\
**Хранение исходного кода:** GitHub\

---

## 1. Цель проекта

Разработать приложение для Windows 10, позволяющее преобразовать локальный принтер, подключённый к компьютеру через USB или другой локальный интерфейс, в полноценный сетевой принтер, доступный другим устройствам локальной сети.

Приложение должно эмулировать сетевой принтер, поддерживать выбор физического сетевого интерфейса, настройку IP-адреса через DHCP или статическую конфигурацию и обеспечивать передачу заданий печати на выбранный локальный принтер.

Приложение должно собираться с использованием Docker, при этом результатом сборки должен быть готовый исполняемый файл `.exe`, предназначенный для запуска непосредственно в Windows 10.

## 2. Основные функциональные требования

### 2.1. Эмуляция сетевого принтера

Приложение должно:

- Создавать виртуальный сетевой принтер.
- Делать его доступным для обнаружения в локальной сети.
- Принимать задания печати с других компьютеров и устройств.
- Передавать полученные задания на выбранный физический принтер.
- Поддерживать одновременное подключение нескольких клиентов с последовательной обработкой заданий.
- Обеспечивать журналирование операций печати.
- Отображать состояние виртуального и физического принтеров, если необходимая информация доступна через драйвер.

### 2.2. Работа с сетевыми интерфейсами

Приложение должно предоставлять возможность выбора сетевого адаптера компьютера, через который будет работать виртуальный сетевой принтер.

Поддерживаемые варианты:

- Ethernet.
- Wi-Fi (при наличии технической совместимости).
- Другие поддерживаемые сетевые адаптеры Windows.

Для каждого интерфейса необходимо отображать:

- Наименование.
- MAC-адрес.
- Текущий IPv4-адрес.
- Маску подсети.
- Шлюз.
- Состояние подключения.

### 2.3. Настройка IP-адреса

Необходимо реализовать два режима сетевой конфигурации.

**Режим DHCP**

- Автоматическое получение IP-адреса от DHCP-сервера локальной сети.
- Отображение выданного IP-адреса.
- Отслеживание изменения сетевых параметров.
- Восстановление доступности принтера при изменении IP.

**Режим Static IP**

Пользователь должен иметь возможность вручную задать:

- IP-адрес.
- Маску подсети.
- Шлюз.
- DNS-серверы при необходимости.

Приложение должно проверять корректность сетевых параметров и предупреждать о возможных конфликтах IP-адресов.

### 2.4. Работа в режиме Bridge

Необходимо предусмотреть возможность работы виртуального принтера как самостоятельного сетевого устройства, имеющего собственный IP-адрес в локальной сети.

Требования:

- Подключение через выбранный физический сетевой интерфейс.
- Доступность виртуального принтера для других устройств в одной локальной сети.
- Поддержка DHCP или статического IP для виртуального сетевого интерфейса.
- Возможность работы виртуального принтера независимо от IP-адреса основного сетевого интерфейса компьютера.
- Минимальное влияние на существующее сетевое подключение Windows.

**Важное техническое условие:** стандартный Docker Desktop на Windows 10 не предоставляет контейнерам полноценный прямой L2 bridge к физической сети. Разработчик должен предусмотреть отдельный механизм виртуального сетевого адаптера, сетевого моста Windows либо другую совместимую технологию. Реализация настоящего Bridge должна быть проверена экспериментально. Простая публикация порта через Docker не считается реализацией полноценного Bridge.

Дополнительно допускается режим совместного использования IP-адреса Windows, если полноценный Bridge недоступен. Этот режим должен быть явно обозначен в настройках.

## 3. Подключение физического принтера

Приложение должно автоматически обнаруживать принтеры, установленные в Windows 10.

Функциональные требования:

1. Получение списка принтеров Windows.
2. Выбор физического принтера, на который будет направляться печать.
3. Поддержка USB-принтеров.
4. Поддержка принтеров, подключённых через другие интерфейсы и установленных в Windows.
5. Проверка доступности выбранного принтера.
6. Передача заданий через Windows Print Spooler.
7. Отображение очереди печати и ошибок.
8. Возможность отмены задания, если это поддерживается системой печати.

Приложение должно использовать существующий драйвер выбранного принтера.

Необходимо предусмотреть преобразование входящих заданий в формат, поддерживаемый драйвером или физическим принтером. Передача необработанных RAW-данных допускается только для совместимых форматов.

## 4. Сетевые протоколы

Предусмотреть поддержку следующих протоколов:

| Протокол | Назначение |
|---|---|
| TCP 9100 (RAW/JetDirect) | Приём заданий печати |
| IPP | Стандартная сетевая печать |
| mDNS / DNS-SD | Автоматическое обнаружение |
| HTTP | Локальный интерфейс управления |

Поддержка AirPrint и Mopria рассматривается как дополнительная функция при наличии совместимого IPP-сервиса и необходимых форматов печати.

Сетевые службы должны работать только на выбранном интерфейсе либо на указанных в настройках IP-адресах.

## 5. Пользовательский интерфейс

Разработать графический интерфейс для Windows 10.

Главное окно приложения должно содержать следующие разделы.

**Сеть**
- Выбор сетевого интерфейса.
- Выбор DHCP или Static IP.
- Настройка Bridge.
- Отображение текущего IP-адреса и параметров подключения.

**Принтер**
- Список обнаруженных принтеров Windows.
- Выбор основного физического принтера.
- Название виртуального сетевого принтера.
- Проверка состояния.
- Тестовая печать.

**Службы**
- Запуск и остановка эмуляции.
- Автоматический запуск вместе с Windows.
- Состояние сетевых служб.
- Информация о клиентах.

**Журнал**
- Время получения задания.
- IP-адрес клиента.
- Наименование задания.
- Статус выполнения.
- Сообщения об ошибках.

Приложение должно иметь возможность сворачивания в системный трей Windows.

## 6. Сборка приложения через Docker

Сборка проекта должна выполняться с использованием Docker.

Основные требования:

1. В корне репозитория должен находиться `Dockerfile`.
2. Должна быть предусмотрена сборка приложения под Windows 10 x64.
3. Результатом сборки должен быть готовый `LANPrint.exe`.
4. EXE-файл должен автоматически сохраняться в корневой каталог проекта на компьютере, из которого выполняется сборка.
5. Пользователь не должен вручную извлекать EXE из контейнера.
6. Должен быть подготовлен автоматизированный скрипт сборки.
7. Все версии используемых SDK, библиотек, базовых Docker-образов и зависимостей должны быть зафиксированы.
8. Сборка должна быть воспроизводимой.
9. Необходимо исключить попадание временных файлов в итоговый выпуск.

**Docker используется в качестве среды сборки Windows-приложения.** Готовый EXE должен запускаться в Windows 10 без необходимости постоянно держать запущенный Docker.

Если для функционирования настоящего Bridge понадобятся системные драйверы или дополнительные компоненты, их установка должна быть отдельно документирована.

## 8. Требования к GitHub

Исходный код проекта должен храниться в репозитории GitHub.

Необходимо:

- Разместить полный исходный код.
- Добавить Dockerfile и конфигурацию сборки.
- Добавить файл README.md с описанием проекта.
- Добавить инструкции для Windows 10.
- Разместить ТЗ.
- Указать используемые версии зависимостей.
- Настроить GitHub Actions для автоматической сборки при выпуске новой версии.
- При успешной сборке публиковать EXE в разделе GitHub Releases.
- Использовать семантическое версионирование, например `v1.0.0`.
- Для опубликованных EXE формировать SHA-256 контрольные суммы.

Исходный код, конфигурация и опубликованный EXE должны соответствовать одной версии.

2. Клонирование репозитория.

## 10. Надёжность и безопасность

Программа должна:

- Корректно восстанавливаться после потери сетевого соединения.
- Не завершаться аварийно при отключении принтера.
- Иметь ограничения размера заданий и количества одновременных подключений.
- Предоставлять возможность ограничения доступа по IP-адресам и подсетям.
- Защищать интерфейс администрирования.
- Предотвращать бесконтрольное накопление временных файлов.
- Корректно освобождать сетевые порты после остановки.
- Не изменять системную конфигурацию сети без согласия пользователя.
- Выполнять привилегированные действия только при необходимости.

## 12. Критерии приёмки

Проект считается выполненным, если:

1. Разработано работоспособное приложение для Windows 10.
2. Сборка полностью автоматизирована через Docker.
3. Готовый LANPrint.exe создаётся в корневой папке проекта.
4. Программа обнаруживает локальные принтеры Windows.
5. Пользователь может выбрать физический принтер и сетевой интерфейс.
6. Поддерживается настройка DHCP и Static IP в предусмотренных сетевых режимах.
7. Реализована и проверена возможность отдельного сетевого IP в Bridge-режиме либо документировано техническое ограничение с согласованной альтернативой.
8. Принтер доступен другим компьютерам локальной сети.
9. Поддерживаемые задания печати успешно передаются на физический принтер.
10. Предоставлены инструкции установки, настройки, сборки и эксплуатации.
11. Исходники размещены в GitHub, а EXE доступен для скачивания через GitHub Releases.
12. Основные функциональные сценарии успешно проходят тестирование.

- Подключение к физическому принтеру Windows.
- Поддержку сетевых режимов DHCP/Static и согласованной реализации Bridge.
- Графический интерфейс управления.
- Инструкции по установке, сборке и запуску.
