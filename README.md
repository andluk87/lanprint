# LANPrint 0.2.0

Windows 10 x64 приложение для локального принтера. Программа создаёт **собственный виртуальный сетевой адаптер** `vEthernet (LANPrint-Printer)` с отдельной MAC и IPv4 из вашей LAN. Физический Ethernet используется только как uplink внешнего Hyper-V коммутатора. Службы принтера слушают исключительно виртуальный адаптер; Shared IP и прямой запуск на физическом интерфейсе отключены.

## Первый запуск

1. Нужны Windows 10 Pro/Enterprise/Education, поддержка Hyper-V/аппаратной виртуализации и Ethernet. Windows Home и Wi-Fi в этой реализации не поддерживаются; автоматического перехода на IP компьютера нет.
2. Скачайте `LANPrint.exe` из [Releases](https://github.com/andluk87/lanprint/releases), проверьте SHA-256 и запустите на Windows. Docker и Go на Windows не нужны.
3. В списке «Подключение к LAN» выберите физический Ethernet. Укажите VLAN ID (1–4094 для tagged VLAN, 0 для untagged), затем нажмите **«Создать / VLAN…»** и подтвердите действие/UAC. Настройка встроена в EXE; скачивать PowerShell скрипт отдельно не требуется.
4. Если Hyper-V ещё не включён, приложение включит его без автоматической перезагрузки. Перезагрузите Windows и повторите создание адаптера.
5. Программа создаст внешний switch (либо использует существующий на выбранном Ethernet), отдельную виртуальную карту и запросит DHCP на ней. Основное соединение может кратковременно прерваться: делайте это с локальной консоли.
6. В секции «Адаптер принтера» появится только `vEthernet (LANPrint-Printer)` с отдельным IP. Если DHCP недоступен, задайте Static IP именно на этом адаптере.
7. Выберите физический принтер Windows, сохраните настройки, настройте Firewall на виртуальный интерфейс и нажмите «Запустить» / «Тестовая печать».

Если виртуального адаптера ещё нет, «Запустить» также предлагает его создание. Если адаптер создан, но DHCP адрес ещё не выдал, приложение ожидает его и запускает службы после появления пригодного IPv4. При загрузке настроек предыдущих версий адрес физического адаптера больше не используется.

## VLAN и мост

```mermaid
flowchart LR
  LAN[LAN: DHCP в VLAN N] <-->|802.1Q VLAN N| ETH[Физический Ethernet uplink]
  ETH <--> SW[Внешний VLAN-aware switch Hyper-V]
  SW <-->|Порт Access VLAN N| NIC[Виртуальный адаптер LANPrint]
  NIC --> IP[Отдельная MAC и IPv4 через DHCP / Static]
  IP --> PRINT[IPP / TCP 9100 / mDNS / HTTP]
```

Поле VLAN ID выбирает VLAN для порта **виртуального** адаптера в мосте. На физическом uplink кадры идут с 802.1Q тегом, Hyper-V снимает тег перед передачей Windows виртуальному интерфейсу и добавляет его при отправке. Отдельного driver-specific VLAN подинтерфейса на физической NIC приложение не создаёт: Windows использует VLAN-aware внешний switch. Не требуется менять VLAN всей физической карты и основного подключения ПК.

На порту физического коммутатора разрешите нужную VLAN (trunk/tagged); DHCP сервер и шлюз должны обслуживать эту VLAN. Это одна Access VLAN на выделенной NIC, не многовлановый trunk внутри Windows. Смена VLAN выполняется кнопкой «Создать / VLAN…» при остановленных службах, с подтверждением/UAC. DHCP lease обновляется на виртуальном адаптере; существующий Static IP сохраняется и требует проверки подсети новой VLAN.

## Docker-сборка на Linux VPS

Нужны Git и Docker Engine с BuildKit. Go 1.24.7 и образ зафиксированы в Dockerfile по версии/digest; сторонних Go библиотек нет.

```bash
git clone https://github.com/andluk87/lanprint.git
cd lanprint
bash build.sh
```

EXE и SHA-256 автоматически появятся в корне проекта. Скачайте их с VPS через SCP/SFTP:

```powershell
scp user@YOUR_VPS:/path/to/lanprint/LANPrint.exe .
scp user@YOUR_VPS:/path/to/lanprint/LANPrint.exe.sha256 .
Get-FileHash .\LANPrint.exe -Algorithm SHA256
.\LANPrint.exe
```

В облачной рабочей среде компиляция не запускается. GitHub Actions выполняет тесты, Windows-target vet и сборку EXE **в Docker**, затем публикует выпуск по тегу соответствующей версии.

## Печать и управление

- Нативный GUI: физический uplink и отдельный виртуальный endpoint, DHCP/Static, список принтеров, состояние, тестовая страница, очередь Windows, отмена, журнал и трей.
- TCP 9100: по умолчанию UTF-8 текст через GDI/драйвер; RAW passthrough включается отдельно для совместимого PCL/PostScript/PDL.
- Базовый IPP по `ipp://VIRTUAL_IP:8631/ipp/print`: UTF-8 текст, PNG, JPEG; RAW только при явном включении.
- mDNS/DNS-SD объявления с IP виртуального адаптера; HTTP управление на `http://VIRTUAL_IP:8765/` с Bearer-токеном.
- Ограничения размера/очереди/клиентов, CIDR ACL, последовательная передача в Spooler, ротация журнала, автозапуск при входе пользователя.

PDF/Office, полный IPP Everywhere, AirPrint/Mopria и IPPS не реализованы. `spooled` означает передачу Windows Spooler, а не подтверждение выхода листа. USB-принтер должен быть установлен с драйвером в Windows. Приложение — пользовательский процесс, не системная служба до входа пользователя.

**Аппаратная приёмка Windows/USB/Hyper-V/DHCP/отдельного IP пока не выполнена.** Linux Docker tests и кросс-сборка не доказывают работоспособность L2 bridge на вашем оборудовании. Проверьте два разных MAC/IP в LAN и реальную печать со второго компьютера.
